- [x] **Block 18 `[core]`** — dense vectors moved from FalkorDB to Qdrant
  - **why**: FalkorDB's vector index exposes only `dimension`/`similarityFunction`/HNSW params — verified against the running instance that it has **no quantization option**, so every 1536-dim embedding sits in RAM as ~6 KB of float32. That RAM ceiling was the only real scaling reason to add a second store; Qdrant gives int8 scalar quantization (~4x smaller) with originals on disk and rescoring
  - `graph/vector_store.py`: Qdrant 1.19 collection (cosine, `on_disk=True` vectors, `ScalarQuantization` int8 `always_ram=True`), `upsert_vectors`/`search`/`find_similar_uid`/`delete_vectors`/`count`, plus a process-wide lazy `client()` so no existing call signature had to change
  - **design rule made explicit**: the graph is the source of truth, Qdrant is a *rebuildable projection*. Qdrant therefore stores only `(uid, label, vector)` — no ACL, provider, or `deleted_at`. All authorization/lifecycle filtering stays in FalkorDB and is applied to the uids Qdrant returns, with `OVERFETCH_FACTOR=4` to absorb the post-filter recall loss and Qdrant's ranking preserved (RRF depends on rank order)
  - **score-semantics inversion handled deliberately**: FalkorDB returned a cosine *distance* (0 = identical), Qdrant returns a cosine *similarity* (1.0 = identical). A threshold ported straight across would have silently stopped matching anything. Verified through Qdrant with real embeddings: identical `1.0000`, near-duplicate `0.9596`, unrelated `0.2036`; `find_similar_uid` keeps its caller-facing `max_distance` unit and converts internally
  - `graph/schema.py` no longer creates FalkorDB vector indexes; `VECTOR_LABELS` remains as the definition of which labels are embeddable
